# Garby — AI Content Authenticity Platform

> Drawing a definitive line between content born from a human heart and content generated by bits.

---

## What is Garby?

Garby is an AI-powered SaaS platform that scans and classifies images and videos as either **AI-Generated** or **Real** — in real time, with a confidence score and forensic signal breakdown.

## Getting Started

### Prerequisites
- Node.js >= 20.x
- npm >= 10.x

### 1. Clone the repo
```bash
git clone https://github.com/garby-app/garby.git
cd garby
```

### 2. Install dependencies
```bash
# Frontend
cd frontend && npm install

# Backend
cd ../backend && npm install
```

### 3. Set up environment variables
```bash
# Frontend
cp frontend/.env.example frontend/.env.local

# Backend
cp backend/.env.example backend/.env
```

Fill in all required values (see Environment Variables section below).

### 4. Run in development
```bash
# Frontend (http://localhost:5173)
cd frontend && npm run dev

# Backend (http://localhost:3001)
cd backend && npm run dev
```

## Environment Variables

### Frontend (`frontend/.env.local`)
```
VITE_API_URL=http://localhost:3001
VITE_SUPABASE_URL=your_supabase_url
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
```

### Backend (`backend/.env`)
```
PORT=3001
NODE_ENV=development
DATABASE_URL=your_supabase_postgres_url
SUPABASE_URL=your_supabase_url
SUPABASE_SERVICE_KEY=your_supabase_service_key
HIVE_API_KEY=your_hive_api_key
SIGHTENGINE_USER=your_sightengine_user
SIGHTENGINE_SECRET=your_sightengine_secret
AWS_ACCESS_KEY_ID=your_aws_key
AWS_SECRET_ACCESS_KEY=your_aws_secret
AWS_S3_BUCKET=garby-uploads
AWS_REGION=us-east-1
REDIS_URL=your_redis_url
JWT_SECRET=your_jwt_secret
FRONTEND_URL=http://localhost:5173
```

> ⚠️ **NEVER commit `.env` files. All secrets must go through GitHub Actions Secrets or Vercel environment variables.**

## Branch Strategy

| Branch | Purpose |
|---|---|
| `main` | Production — protected, requires PR + review |
| `staging` | Staging environment — auto-deployed |
| `dev` | Active development base branch |
| `feat/*` | Feature branches — branch from `dev` |
| `fix/*` | Bug fix branches |
| `chore/*` | Tooling, deps, config changes |

### Branch Protection Rules (main)
- Require pull request before merging
- Require at least 1 approving review
- Require status checks to pass (lint, test, build)
- No direct pushes
